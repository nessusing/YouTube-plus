# F-17 YouTube 改版后接管失灵要能发现

**what**：队列（F-05）靠 YouTube 的内部接口和页面结构接管「加入队列」。YouTube 改版后接管可能悄悄失灵——菜单上照样写着「加入 <列表名>」，点了却进了官方临时队列。要让这种情况能被发现。背景见 [research/2026-11-22-队列依赖YouTube内部结构.md](../research/2026-11-22-队列依赖YouTube内部结构.md)。

**验收标准**

1. 接管失灵检测（先做）
- F-17-AC1 接管中，用户点了扩展改过文字的菜单项或悬停按钮，几秒内没拦到对应的「加入队列」动作，就算失灵：弹页面提示（F-02）「没能加入 <列表名>，可能是 YouTube 改版了」，并写日志（带当时的菜单类型、命令结构）。
- F-17-AC2 同一个标签页只提示一次。
- F-17-AC3 这些正常情况不算失灵：F-05-AC5 里的例外（已有官方队列且迷你播放器开着时点缩略图）；菜单项被点了但菜单其实没执行（比如点到别处关掉了）。

2. 启动自检（后做）
- F-17-AC4 进入接管时检查要用的 YouTube 内部方法和数据在不在；缺了写一条警告日志，列出缺哪些，不提示用户（这些都有退路，功能还能用）。例外：分辨身份用的数据缺失时要提示用户（没有它分不出频道，F-05-AC1）。
- F-17-AC5 每个标签页查一次；要等的对象比页面晚出现时等它出现再查，等不到也记一条日志。
