TASKS 里 F-03 下几条 bug / 改进的原始材料。

## 一个视频被拒，整批都失败（TASKS：F-03 bug，原 P16）
- 2026-11-20 20:21–20:22，连续 3 批回答都是「违反政策」的拒绝，三批里都有同一个视频。一个视频被拒，整批 5 个都记成「答案里缺了」的 `transient`；重试时它又被分进下一批，把别的视频一起拖下水。
- 2026-11-20 01:03 还有一批回答「I'm having a hard time fulfilling your request」，可能是同类问题。
- 定下的改法：整批没解析出任何结果时，拆成单个视频重试一次；单个也被拒的视频标成不能总结（不再算 `transient`），不再进批。（个性化设置 F-03-AC6 的兜底也一起做。）

## 批量回答像 JSON 却没解析出来（TASKS：F-03 bug，原 P17）
- 2026-11-21 01:15 一批，回答开头是正常的 JSON 数组（`"id"`、`"status":"ok"` 都在），结果 5 个全记成「答案里缺了」。日志只记了前 500 个字符，看不出原因。同一批要求中文，`points` 却是英文（`lang` 写的是 `zh`）。
- 2026-11-20 12:26 有两次 `no answer text in 136 bytes`（`protocol`），也没留下原文。
- 测个性化设置时在网页 UI 里抓到两种（7 次里各 1 次）：
  - **数组输出两遍** `[...][...]`：旧的正则从第一个 `[` 匹配到最后一个 `]`，解析失败。
  - **JSON 本身写坏**：某个对象里出现 `"lang":"zh","yue",`。
- 2026-11-21 已改：按括号配对解析（跳过字符串里的括号），取第一个由对象组成的数组；整段不合法时逐个对象解析，坏的算缺。
- 还差：解析失败时把模型的完整回答记进日志（只记回答，不记请求）。语言不对的问题等有更多例子再看。

## 凭证缓存（TASKS：F-03 改进，原 P2）
- 现状：生成和删除对话各自先抓一次 `/u/N/app` 页面拿 token，每批 4 个请求里 2 次是抓页面。浪费的是 HTTP 请求不是 Gemini 额度，但增加延迟，流量也更像机器。
- 方案：token 按账号缓存几分钟，换账号时清掉；遇到 400 / 405 时清缓存、重抓、重试一次，还失败按现有错误处理；自检和「我已登录」检测仍然实时抓；`processSession` 用的 API key 一起缓存。两条通道和删对话都用这组凭证，跟走哪条通道无关。
- 2026-11-20 决定先不做；跟协议迁移无关，随时可以做。
