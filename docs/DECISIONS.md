## D-001 · 2026-11-14 · 技术栈：WXT + TypeScript + 原生 DOM
状态：生效
背景：要做一个 Chrome MV3 扩展，包含多个互相独立的功能。
决定：WXT + TypeScript；界面用原生 DOM / Shadow DOM，不用前端框架。单元测试用 Vitest，真实 YouTube 上的测试用 Playwright。
原因：保持轻量；注入 YouTube 页面的界面用 Shadow DOM 隔离样式。
影响：全部

## D-002 · 2026-11-14 · 零成本：用浏览器已登录的账号，不用 API key / OAuth
状态：生效
背景：TL;DR 要用 AI，队列要读写 YouTube 播放列表。
决定：所有外部服务都借用浏览器里已登录的 Google 账号（YouTube、Gemini 网页版），不申请 API key、不走 OAuth。
原因：自用、零配置、零费用。
影响：F-03、F-05、F-12

## D-003 · 2026-11-21 · 贴合官网
状态：生效
背景：扩展语言要不要单独设置的讨论里提出，上升为通用原则。
决定：能从 YouTube 官网拿到的（账号、播放列表、语言等）直接用，不另存、不让用户再设；界面和交互仿官网。
原因：少一份要同步的状态，少一个设置项；看起来像 YouTube 自己的功能。
影响：全部，尤其 F-04、F-05

## D-004 · 2026-11-18 · TL;DR 用 Gemini 网页版的内部接口
状态：生效
背景：需要一个免费的、能直接读 YouTube 视频的 AI。
决定：后台调用 Gemini 网页版（逆向内部接口），借用它的 YouTube 应用读视频。用普通对话（临时对话用不了 YouTube 应用），生成完立即删除。要求用户开 Gemini 应用活动记录并启用 YouTube 应用。
原因：免费、零配置（D-002），Gemini 直接读得到视频内容，扩展不用自己抓字幕。
代价：接口随时可能变（F-03-AC13 自检会报 `protocol`）；接受封号风险；没字幕的视频读不了。
影响：F-03、F-12

## D-006 · 2026-11-21 · `processSession` 优先，`StreamGenerate` 后备；官方 API 往后放
状态：生效
背景：Gemini 网页前端 2026-10 起改用 `processSession`（WebChannel 协议），担心旧的 `StreamGenerate` 下线。原计划先做官方 API（F-13）当后备。
决定：实现 `processSession` 并优先用，`StreamGenerate` 当后备，两条互为后备（F-03-AC7）。官方 API Provider（F-13）暂停。
原因：原型证明 YouTube 应用在新协议下能用，有两条网页通道已经够；官方 API 要用户填 key，不再零配置。
影响：F-03、F-13

## D-007 · 2026-11-21 · 扩展语言跟随 YouTube；TL;DR 用视频自己的语言
状态：生效
背景：设置页原来有语言选项；TL;DR 原来按扩展语言写要点。
决定：扩展界面语言 = YouTube 界面语言（`zh*` → 中文，其他 → English），去掉设置页的语言选项，不留手动覆盖。TL;DR 要点用视频自己的语言，任何语言都是，由 Gemini 判断；缓存不再按扩展语言分。（同一天先定过「中英以外用扩展语言」，当天取消。）
原因：贴合官网（D-003）；让 Gemini 判断语言比读元数据、按标题判断都准，还不多花请求（见 research/2026-11-21-TLDR视频语言判断.md）。
代价：做不到「YouTube 用英文、扩展用中文」。
影响：F-03、F-04

## D-008 · 2026-11-20 · 队列做成「自带队列 / 播放列表当队列」二选一
状态：生效
背景：最早的设计是把官方队列同步到一个私密播放列表（2026-11-18），重新设计。
决定：设置里二选一：YouTube 自带队列（扩展不管）或用一个播放列表当队列（接管所有走 `yt-action` 的「加入队列」入口）。设置按身份（频道）分开存；没选列表或无权编辑时不接管；切换模式不迁移数据；「播放完后删除」默认勾选。
原因：播放列表存在账号里，天然跨标签页、跨设备；用户可以随时退回原生行为。
影响：F-05、F-06、F-10、F-17

## D-012 · 2026-11-22 · 评论弹幕的定位：本地默认，AI 可选
状态：生效
背景：没带时间戳的评论要决定放在哪个时刻。
决定：默认用本地算法按热度撒到全片；可选让 Gemini 读字幕定位，只信置信度 ≥ 0.9 的；AI 用不了时按设置退回。AI 请求优先于 TL;DR，不占每小时 / 每天上限，但受熔断约束。
原因：本地方式免费、稳定、同一视频结果一致；实测 Gemini 低置信度的定位不准（见 research/2026-11-22-评论弹幕实测.md）。
影响：F-12

## D-013 · 2026-11-22 · 评论弹幕挪到播放器顶部，仿官方字幕
状态：生效
背景：原 P26。
决定：字幕卡放在播放器顶部居中，仿官方字幕的胶囊底，避开顶部标题栏和显示在上半部分的字幕；不能拖。
原因：（2026-11-22 用户确认）很多视频（尤其中文的）有烧进画面的字幕，检测不到，放在下面会重叠；放在上半部分跟画面内容重叠的可能性小得多。现有的弹幕系统大多也默认在视频上半部分显示。
影响：F-12

## D-014 · 2026-11-22 · 列表页缩略图只换动图，不真播放
状态：生效
背景：想让列表页上的缩略图同时动起来。
决定：只把缩略图换成动图（优先用 YouTube 自带的几秒动图），不开播放器、不放 iframe。
原因：真播放要么受限于 YouTube 只有一个预览播放器，要么每个 iframe 几十 MB 内存、各占一路视频流，还可能触发风控（见 research/2026-11-22-列表页缩略图动起来.md）。
影响：F-22

状态：「谁跑 L4」部分被 D-021 取代；分层和测试列表的规则仍生效
背景：很多行为只能在真实 YouTube 上验证，要登录、会碰账号里的列表。
决定：L1 纯函数、L2 controller 集成（内存里的假 YouTube）用 `npm test`，AI 自己跑；L4 在真实 YouTube 上（Playwright），`npm run test:e2e` / `npm run test:all` 只由用户跑。L4 只碰名字以 `YouTube+ e2e` 开头的列表，用跨运行保留的小池（YouTube 限制每天新建列表数）。界面和 Gemini 相关的部分另靠设置页自检和手测。

## D-019 · 2026-11-21 · 发弹幕作为带时间戳的公开评论发出
状态：生效

## D-021 · 2026-11-23 · 单个 bug / feature 的 L4 由 AI 跑，从头到尾的全跑由用户跑
状态：生效
背景：D-016 让 L4 全部由用户跑，结果修一个小 bug 也要交给用户跑一条测试、贴输出，来回成本高。
决定：AI 正在改的 bug / feature 相关的测试（包括 L4 里单个 spec 文件或用 `-g` 选出的用例）由 AI 自己跑；`npm run test:all`、完整的 `npm run test:e2e` 这种从头到尾走一遍的由用户跑。L4 只碰 `YouTube+ e2e` 开头的列表、视频静音（D-017）的规则不变。
原因：针对性的测试快、范围小，AI 自己跑才能做到「先看回归测试失败再修」；全跑慢、动的东西多，由用户决定什么时候跑。
影响：全部；取代 D-016 里「L4 只由用户跑」这一条。

## D-022 · 2026-11-23 · L4 的偶发失败和 YouTube 行为不同
状态：生效
背景：L4 跑在真实 YouTube 上，有两类失败不是扩展的问题：一是时机、网络造成的偶发（单跑又过）；二是测试账号上 YouTube 的行为和官网不同（比如 A/B 试验：测试账号按 Esc 关不掉迷你播放器，用户自己的 Chrome 能关）。原来只有通过 / 失败两种结果，两类都算失败。
决定：L4 失败后自动重试 1 次，不多试；重试才过的报告为 flaky（第三种结果），不算失败，但记进 TASKS，同一条反复 flaky 就把测试改稳。测试依赖的 YouTube 官方行为在测试账号上不成立时，测试先确认官方行为，不成立就跳过那一步并注明原因（报告里能看到），不算失败。持续失败不靠重试掩盖。
原因：偶发和外部变化不该跟真 bug 混在一起；多试几次只会把真问题盖住。
影响：L4 全部；全跑结果多一个 flaky 数。
