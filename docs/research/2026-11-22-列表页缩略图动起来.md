# 列表页缩略图同时动起来：为什么只做动图、图源有哪些（2026-11-22）

F-22 的材料。

## 为什么不真播放
- YouTube 自己的悬停预览只有一个播放器（`ytd-video-preview`），悬停到哪张卡片就挪到哪里，同一时间只能放一个。用内部接口多造几个播放器也许可行，但每个都是完整的播放器，开销跟 iframe 差不多，还要靠没有文档的接口，可能跟页面自己的预览打架。
- 每张卡片放一个 `embed` iframe（静音自动播放）能真播放，但每个 iframe 都是一整套播放器，要几十 MB 内存，还各占一路视频流。整页二三十个会卡，还可能触发风控；有些视频禁止嵌入。以后真要做「多宫格同时看」再单独立项，最多同时放 4～6 个，只放看得见的。

## 图源实测（2026-11-25）

用 e2e 测试账号的 Chromium（无头、静音，只读页面）。脚本在 scripts/thumbs/。

### 1. YouTube 自带的 3 秒动图（`i.ytimg.com/an_webp/…`）
链接在页面数据里，不用另发 API 请求。带签名，去掉签名是 404。每张 320x180、110–150 kB，浏览器缓存 6 小时。

| 页面 | 带动图链接的视频卡片 | 数据里的位置 |
|---|---|---|
| 搜索 | 39 / 39 | `videoRenderer.richThumbnail.movingThumbnailRenderer.movingThumbnailDetails.thumbnails[].url` |
| 频道「视频」 | 90 / 90 | `lockupViewModel` 里的 `thumbnailViewModel.overlays[].animatedThumbnailOverlayViewModel.thumbnail.sources[].url` |
| 频道首页 | 141 / 143 | 同上 |
| 观看页侧栏 | 59 / 60 | 同上 |
| 历史记录 | 73 / 82 | 同上 |
| **首页** | **0** | 没有 |
| **订阅页** | **0** | 没有 |
| 播放列表、赞过的视频 | 0 | 没有 |
| 各页的 Shorts 卡片 | 0 | 没有 |

首页和订阅页换成普通浏览器的 UA 再查，仍然是 0。这两页悬停时放的是内嵌播放（`player` 请求加视频流），不用动图。按视频 ID 调 `search` 拿链接：6 个只中 3 个，每次回应 60–660 kB，不可用。

### 2. 自动截帧（`i.ytimg.com/vi/<ID>/mq1.jpg`、`mq2`、`mq3`）
YouTube 给每个视频在前、中、后各截一帧。不用签名，不用 API，只凭视频 ID。
- 混合样本 266 个视频（首页、订阅、历史、搜索、Shorts、播放列表）里 259 个有（97%）；没有的返回 120x90 的灰色占位图。
- `mq*` 320x180、每张 5–12 kB；`hq720_*` 1280x720、每张 75–150 kB（40 个里 36 个有）。浏览器缓存 5 分钟。
- 效果是三张静态图轮换，不是连续动作。

### 3. storyboard 雪碧图
- 每个视频要发一次 `player` 请求（带 `signatureTimestamp`，不带会返回 UNPLAYABLE），实测一次约 217 kB、0.1–0.7 秒；首页一屏二三十个、滚下去上百个。
- 最大一档 320x180、每隔几秒一帧；另外还要下载雪碧图。
- 帧覆盖全片，比方案 2 信息多，但请求量大，有触发风控的风险。

## 页面结构（2026-11-25，实现前和 L4 时确认）
- 动图链接只在页面元素的 `data` 属性里（页面脚本世界才读得到）。挂的层级各页不同：搜索在卡片自己（`ytd-video-renderer`），频道「视频」在上两层的 `ytd-rich-item-renderer`，观看页侧栏和历史记录在 `ytd-item-section-renderer`，频道首页在上四层的 `yt-horizontal-list-renderer`。站内换页后一样。
- 动图是无限循环的 webp（约 19 帧、3 秒）。
- 缩略图两种结构：新版 `yt-thumbnail-view-model` > 图片层 + 角标层；旧版 `ytd-thumbnail a#thumbnail` > `yt-image` + `#overlays`。图盖在图片层后面、角标层前面。
- 搜索结果并不是每张都有动图链接；有些搜索词首屏全是做成横版卡片的 Shorts（链接是 `/shorts/`）。

## 用户实测反馈（2026-11-25，D-029）
- 可轮换的画面太少（3、4 张），看不出视频讲什么。
- 卡顿的播放让人有眩晕感。
- 对照三种图源：截帧只有 3 张、每秒换一张；官方动图抽查的一个是 3 秒约 19 帧（约每秒 6 帧），内容也只有这几秒；storyboard 帧多、覆盖全片，但每隔几秒一帧，仍然是跳着放。三种都做不到流畅连续。
